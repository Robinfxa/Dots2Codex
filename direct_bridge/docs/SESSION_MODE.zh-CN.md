# Direct 单会话 CLI

这是当前多路由后端的正式配置范围选项，不调用已归档的单路 trial、一次性标记或 `REOPEN` 协议。

## 启动

双击根目录 `DIRECT.command`，选 **1 Start → 1 单会话 CLI**。命令行可直接运行 `./DIRECT.command session`；`./DIRECT.command start` 和 `global` 明确表示全局模式。

先检查已安装的 `codex-cli 0.159.2`，然后选择本次项目目录。可用 `CODEX_BIN` 指定已有二进制；指定路径无效时会报错，不换用另一份。程序不自动安装、升级或降级 Codex。首次设置仍使用现有 Direct 专用 tunnel 和私有凭据目录；所有依赖安装、凭据保存和 profile 创建沿用现有确认流程。

单会话启动使用选定的 `CODEX_HOME` 和正常项目目录，传入：

- `--no-daemon`，避免接入已有共享 daemon
- 新生成的唯一 provider ID 和完整 provider 表，指向身份已核验的本机服务
- 当前允许模型目录以及默认 `gpt-6-astra / xhigh`；后续新路由仍须使用允许的精确 model/effort
- `env_key=DOTS_BRIDGE_HTTP_BEARER`，本地 bearer 只进入 CLI 子进程环境，不进入命令行；隧道 key 和无关 API key 不传给 CLI

不写入、恢复、备份或修改 `CODEX_HOME/config.toml`，不修改 auth.json，也不强制改变现有 sandbox、审批和 web_search 设置。你在 CLI 内主动改变设置的效果由 Codex 本身决定。CLI 的退出码会作为 `session` 命令的退出码返回。

## 共享服务和已有全局配置

“单会话”指临时 provider 参数的范围，**不表示独立服务或隔离已有客户端**。数据库、模型/effort 路由、MCP schema、官方隧道和原生父/子控制器与全局模式相同。CLI 退出、启动失败或取消不会恢复已有的全局配置；已经健康运行的服务不会被它停止。

若本工具已有全局配置/恢复记录，会明确提示单会话不会撤销它。其他客户端仍可能使用 Direct。即使没有本工具的记录，外部已有的 provider 设置也保持原样，不宣称其他窗口已隔离。

共享服务会保持运行，直到明确 Stop。这样一个 CLI 退出不会中断正在工作的 Desktop 或其他 CLI。启动新 CLI 前若当前服务健康、包版本及身份匹配，会直接复用。当前服务正在运行但不健康、包版本变更或身份不符时，单会话不会替你修复、停止或重启它。先查看 Status，在合适时间明确 Stop 后再 Start；不要在另一个工作尚未完成时更新运行中的服务。

## Stop、取消和恢复

- 选模式时输入 0 取消，不建立服务或修改配置；选项目时也可输入 0
- 新建服务在就绪前失败/取消，只清理本次拥有的服务进程，保留已有全局配置和请求记录
- 退出 CLI 不停止后台服务。菜单 0 Exit 也不等于 Stop
- Stop + Restore 会中断所有共享客户端的后续请求，且只恢复本工具管理过的全局配置。检测到本工具记录的活动单会话 CLI 时需再输入 `STOP`
- 只记录本次 launcher 和 CLI 的准确 PID/进程身份。不扫描全机，不关闭用户应用；已退出或 PID 被重用的旧记录不会造成永久锁定
- 例外：本次刚启动的 CLI 若因持续存储故障无法保存拥有者记录，会按准确进程身份回收这个新进程，避免留下不可追踪的使用者；不会回收已有 CLI/Desktop 或共享服务。无法确认回收时会报告失败，不能视为正常退出。停止进程不撤销已经执行的动作，请求记录仍保留
- 活动单会话存在时，全局 Start 可以复用健康服务并在获批后启用全局配置，但不会为了更新/修复暗中重启其服务。请先正常退出相关 CLI，再安排重启
- 记录、路由、请求、未知动作、历史回声兼容修复及原生模型/effort 绑定跨 Stop/Start 保留；不要删除数据库来重试

本地服务启动不会创建、唤醒或替代真实原生控制器。仍需按 [原生控制流程](GLOBAL_NATIVE_CONTROLLER.zh-CN.md) 在 dot 中明确接入。离线合成进程/HTTP测试和 CLI 参数加载不等于实际 Mac、Desktop、隧道或模型多轮闭环已验收。
