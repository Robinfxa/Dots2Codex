# 从下载到验证：给 dot 的自动部署任务

这是可直接执行的任务说明，不是让用户逐步复制命令的教程。请在现有授权内完成下载、检查、两端部署、真实文本验证和清理；能独立完成的步骤直接推进，只在确有权限、能力或安全限制阻塞时提出具体问题。

## 目标和默认范围

从 https://github.com/Robinfxa/Dots2Codex 获取当前源码，记录实际提交版本，并从同一提交读取源码与全部说明。在你自己的已授权云端桌面与命令环境中完成一次最多300秒、1条请求的 text-only 验证。不要默认操作用户的电脑，不要把测试升级为永久后台服务。

角色必须明确：

- 桌面端：官方 Codex CLI 与 loopback HTTP facade，二者处在实际能互通 localhost 的同一环境
- broker端：命令环境中的已活跃、获授权、具有实际推理能力的原生 agent，通过共享文件领取并完成请求
- 协调方：发现能力、安排两端、观察状态和验证结果；不逐条替 broker 转交模型输入或提交回复

## 自动执行流程

1. **下载并检查。** 用当前可用、获授权的仓库下载方式取得源码，放入新的工作目录。阅读 README.md、START_HERE.zh-CN.md、BROKER_HANDOFF.zh-CN.md、RECOVERY.zh-CN.md、ROLE_CONTRACT.json 和 SECURITY.md。运行 `python3 -m unittest discover -s tests -v`，记录通过、失败和跳过项。不要假设任意版本或环境都已兼容。

2. **发现真实能力。** 检查可用的桌面操作、命令执行、原生 agent、文件读写及任务状态工具。核实 Python/POSIX 条件和已有官方 Codex CLI 的实际路径、版本。缺少必要组件、原生推理能力或访问权限时，报告具体阻塞和最小下一步；不要虚构工具、安装未知软件、创建凭据或换路线绕过明确拒绝。

3. **确定两端与共享目录。** 分别观察桌面和命令环境；路径名相同不代表文件、进程或网络相同。确定两端实际可见的同一私有共享目录映射，准备在下一步初始化后做 probe 握手。不要用同一环境的测试冒充跨环境验证。

4. **初始化新部署。** 先准备好可用的两端角色，再选择尚不存在的 BRIDGE_ROOT，由 `portable.py init` 独占创建，设置 `--seconds 300 --max-requests 1`。初始化前的准备记录放在部署目录之外；初始化后才使用 evidence/。不要预建内部 queue 或 isolated-cli。初始化后按标准 probe 的 observe → offer → answer → verify 完成随机 nonce 往返；实际命令顺序和参数以 START_HERE 为准。

5. **启动真实 broker 和桌面 CLI。** 按标准 assign/handoff 分配有界 broker，让它进入有限 claim 等待并回答就绪挑战。桌面端先查看 desktop_bootstrap 的计划，再使用已有且获授权的官方 CLI 执行。保留独立 HOME/CODEX_HOME/workspace、read-only sandbox 和 on-request 审批；不复制认证文件、不改默认配置、不开外网监听、不切换默认模型额度。只处理已授权的新工作区普通信任提示；遇到更广权限要求按实际规则处理。

6. **完成真实文本往返。** 向桌面 CLI 发送随机标记，要求原样回复且不调用工具。broker 按 claim → read → 实际原生推理 → complete → status 执行，必要时在期限内续租，最后 stop。Python 只管理数据，不生成冒充原生模型的回答；不要使用合成 fixture 代替这一步。若已开始的推理结果不明，按恢复协议保留不确定状态，不重复派发。

7. **核验并清理。** 对照同一请求的关联信息，确认队列 completed/delivered，并实际观察 GUI 回复与随机标记一致。正常退出当次 CLI，确认自己的服务、broker 和子进程停止；记录退出方式与清理结果，不把计划到期终止误判为此前推理失败。不要影响用户原有进程、配置或仓库。

## 交付结果

简洁报告：源码/CLI版本、实际两端角色、共享文件探针结果、合成测试与真实文本测试的区别、真实回复是否在GUI显示、队列状态、退出和清理状态，以及每个服务当前是活动还是已停止、配置的TTL和剩余期限；失败则给出具体阶段与最小下一步。保留脱敏证据，不公开原始请求、内部指令、租约、认证文件或私有会话记录。

写outbox只代表本地持久记录。未经实际配置并验证的通知渠道，不得承诺父级自动收到、自动唤醒或24/7运行；环境断开也不单独证明任务已结束。任务结束后不能假装原生broker仍在后台存活。文本往返不代表通用工具执行闭环通过，桥接不承诺免费推理或绕过配额。

## 可选扩展需单独选择

上面的默认任务仍为一次 text-only 验证，不自动打开工具或增加会话。如果用户明确要求固定分配或有界工具任务，先检查 `jsonschema` 4.x 和实际原生任务工具，再按同一提交的 ROUTING_RUNBOOK.md 操作；`tool_probe` 的固定命令见 TOOL_PROBE.md，`repo_review` 的固定仓库读取见 REPO_REVIEW_RUNBOOK.md。后者还要求两端 checkout 的绝对路径一致，并禁止中途更换 worker。

保留新 registry、私有共享目录、明确的会话/请求/工具/时限上限和原有审批边界。协调方只在首次分配或允许的安全换人时调用实际原生任务工具；正常轮次直接交给固定 worker。不要把支持此数据协议说成 Python 会自行启动 agent、永久保活、自动唤醒或执行通用工具。

仓库研究的既有真实测试因 `network_unavailable` 停在首次 tree 请求，未取得仓库内容或 commit。当前分发中的离线多轮测试不能替代在目标环境中的真实成功取数。遇到同类失败时如实报告并正常清理，不扩大网络权限，不绕过明确访问限制。
