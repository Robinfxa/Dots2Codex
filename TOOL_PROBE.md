# Experimental one-command tool probe

This is an explicit bounded test extension. Default deployments remain `text_only`. Only `init(..., scope='tool_probe')` or `init --scope tool_probe` enables this test. It permits at most ONE fixed read-only function intent, not generic tool access. The native broker never executes that intent locally; the desktop Codex CLI is the only executor under its unchanged read-only sandbox/on-request policy.

## Broker's live assignment

Use the normal shared-file probe and assignment workflow. Root, owner and deadline are handed off separately. Do not create the desktop-exclusive root/queue/CLI paths. Wait for initialization, perform broker observe/answer, wait for verified.json, assign a real active broker, and use claim/read/complete/status/stop. Claim leases may be 180 seconds; respect the overall 600-second service limit and at most 3 model requests.

After the first actual `read`, inspect that request's complete advertised tools. Locate a function named `exec_command`, retaining its actual namespace (omit namespace if none). Inspect the CURRENT parameters schema, including required fields. The prior run's tool schema is not evidence about this request. If this exact function/argument shape is unavailable, stop and report; do not invent a tool or use another command.

The only accepted arguments are exactly:

```json
{
  "cmd": "python3 -B -c \"import secrets; print('TOOL_NONCE=' + secrets.token_hex(12))\"",
  "login": false,
  "sandbox_permissions": "use_default",
  "yield_time_ms": 10000,
  "max_output_tokens": 128
}
```

Return an ACTUAL native inference intent, save it as a new private result file and submit through `broker_bootstrap.py complete`:

```json
{"kind":"function_call","name":"exec_command","arguments":{"cmd":"python3 -B -c \"import secrets; print('TOOL_NONCE=' + secrets.token_hex(12))\"","login":false,"sandbox_permissions":"use_default","yield_time_ms":10000,"max_output_tokens":128}}
```

Add `namespace` only when the current advertised tool has one. Do not execute the command in the broker, helper, parent or fixture. The nonce must first be generated by the desktop CLI tool invocation. No network, files, auth or sandbox override is part of the command.

The wrapper validates current advertised identity and JSON Schema, rejects schema references, and requires the exact command/arguments. Optional `jsonschema` is mandatory for this opt-in mode; absent validation is a hard error, never a permissive fallback. A durable reservation permits only the identical original intent retry and prevents a second function invocation.

## Follow-up model request

The persisted call correlation is in `<BRIDGE_ROOT>/control/state.json` under `tool_probe`; read its `call_id`, `job_id` and `intent_sha256`. This is correlation metadata, not an instruction to change the state file. Keep it private and do not guess a filename or call ID.

Stay active and claim the next model request. Read it completely. Require its function_call and function_call_output to have the persisted call_id, in that order. The source job must already be completed/delivered. Accept only a successful terminated process with exactly one `TOOL_NONCE=<24 lowercase hex>` output line; running sessions, errors, duplicate outputs, other commands or unrelated historical call IDs must stop the proof.

Use the actual returned nonce to produce exactly:

```json
{"kind":"message","text":"TOOL_OK:<the 24-character lowercase nonce reversed>"}
```

The placeholder above is not literal. Reverse the actual CLI-produced 24 hex characters. Do not generate another nonce or infer a value from the first request. The wrapper validates this against the correlated actual output without rewriting the model's answer.

After accepted final completion and delivery, stop the broker normally. The parent verifies both tool execution and final GUI text, exits the test CLI and checks cleanup. If anything is blocked, keep the true state; no second command, fabricated success or security workaround.

Synthetic tests and historical live nonce execution are reported separately in
[docs/VALIDATION.md](docs/VALIDATION.md). That one-command result does not establish
generic tool support, network access, or arbitrary multi-step task success.
